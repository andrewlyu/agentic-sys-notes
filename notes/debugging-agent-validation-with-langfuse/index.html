Bad Agent Output or Broken Validator? Debugging an Agentic Workflow with Langfuse

My publication agent produced a draft, but validation blocked it. Before changing the prompt, I needed to answer one question: did the agent break a rule, or could the validator not check it?

I used Langfuse to inspect two different layers: what Codex did, and what the publication application did with its output.

Two traces answer different questions

Capturing application stages alongside model and tool activity follows documented tracing practice: Langfuse recommends recording the important steps of a unit of work, and OpenTelemetry defines agent and workflow spans. Those GenAI conventions are still in Development. Neither source mandates two separate traces; that is my integration choice for this demo.

The architecture has two independent capture paths. Codex session records flow through a transcript plugin into an agent trace. Application stage records flow through an application adapter into a workflow trace. Both are stored in Langfuse for visual inspection and later API queries; they are not automatically one merged trace.

The Codex integration captures model and tool activity without requiring me to rewrite the application around an OpenAI SDK. My application tracing adds the stages and outcomes that matter to publication. It does not require the full-session exporter to be enabled.

What the screenshots reveal

Codex trace: the first screenshot shows a Codex turn with grouped LLM and execution observations. I use this view to locate the model responses and tool calls behind an action.

Application trace: the second screenshot names the publication stages: prepare evidence, draft, validate, compare, and await human review. I use this view to find the stage that blocked progress.

These are aggregated views. Their arrows, grouping, and colors help navigation; they do not by themselves establish execution dependencies or explain why a check failed. I still need the observation details.

The useful finding was in the validator

The source-boundary check asks whether drafting used only permitted material. In this experiment, the checker could not interpret the installed Codex version's session records.

The trace located the validation problem. Local records and code established the version mismatch. I therefore changed the reporting to distinguish verification unavailable from rule violated, while keeping the workflow blocked for human review.

I then queried Langfuse's observations API for the corrected run's validate-preview step. It returned HTTP 200. These four fields are copied from that response; identifiers and unrelated fields are omitted:

{
  "name": "validate-preview",
  "type": "GUARDRAIL",
  "level": "WARNING",
  "statusMessage": "validation=blocked;source verification unavailable;reasons=missing_candidate_write,unsupported_event,unsupported_rollout_version,unsupported_tool,source_boundary_respected,required_claim_coverage,citation_integrity,unsupported_claim_count"
}

The decisive signal is source verification unavailable, with unsupported_rollout_version among the reasons—not the warning color. This is a readback of the improved reporting. The API excerpt alone does not establish the exact version mismatch or prove a forbidden read.

That is not a passing result, and clearer tracing does not repair the parser. It tells me where to work next instead of rewriting the drafting prompt.

Debug after the original session ends

With the reason recorded, I can query observations and scores through the Langfuse API, without resuming the drafting session or loading its entire conversation into another agent.

The limit is what I captured: an API query cannot recover a missing explanation. The original diagnosis still needed local evidence.

Four tracing rules I would keep

  • Keep unknown distinct from false. A checker that cannot read the record has not proved a violation.
  • Time the actual stage. Drafting time should not include the whole enclosing workflow.
  • Record failure reasons and check replay behavior. Langfuse v4 observations are immutable; repeating an ID is not sufficient to prevent duplicates.
  • Keep handoff distinct from approval. Reaching human review does not mean the draft was accepted.

The value is a specific next action: inspect the agent's actions when generation is suspect, inspect the application stage when validation is suspect, and check the instrumentation before trusting either verdict.
